1. НАЗНАЧЕНИЕ
====================================================================

Процедура управляемого омоложения (managed rejuvenation): как система
замечает старение или несоответствие миссии, получает инъекцию от
AI-рибосомы, отбирает её и внедряет — без дрейфа и без потери
восстановимости оригинала.

Связь: AI_INTERPRETER_GOVERNANCE_GUARD_v0_1 говорит «что запрещено»;
эта SOP говорит «как ходить». При противоречии guard имеет приоритет.

Основание: пилот CASE-SOFT-001 (2026-07-30) — петля выполнена вручную
один раз, найден Activation Failure; фабула подтверждена практикой.

====================================================================
2. ПЕТЛЯ (6 ШАГОВ)
====================================================================

  [1] TRIGGER (триггер)        → замечено старение / сигнал о сбое
  [2] REPRODUCE (воспроизведение) → сигнал стал доказанным отказом
  [3] CANDIDATE (кандидат)     → рибосома пишет инъекцию
  [4] SELECT (отбор)           → редактор: принять/изменить/отторгнуть/вернуть
  [5] PROOF (проверка)         → Dynamic Proof Testing
  [6] INTEGRATE+RECORD (внедрение+запись) → установка и custody-запись

Петля повторяется. Каждый проход = один INJECTION_ID.

====================================================================
3. КЛАССЫ ТРИГГЕРОВ
====================================================================

| Класс | Примеры | Что ловит | Природа сигнала |
|---|---|---|---|
| T-INT (внутренний монитор) | упавший CI, устаревшая зависимость, обзор формата по расписанию (SOP: метаданные — год, форматы — 3 года) | старение объекта | точный, но слеп к реальному миру |
| T-EXT (внешняя обратная связь) | отзывы, issues, письма пользователей, репорты | несоответствие миссии | шумный, но видит настоящую нагрузку |

Правило: система обязана держать оба класса. Один стережёт объект,
другой — цель. Отсутствие T-EXT канала у публичного объекта
записывается в риск-регистр.

====================================================================
4. ШЛЮЗ ВОСПРОИЗВЕДЕНИЯ (обязателен)
====================================================================

Сигнал любого класса ≠ отказ. До передачи рибосоме сигнал подтверждается:

- T-INT: повторный запуск показывает тот же отказ (не мигание среды).
- T-EXT: жалоба воспроизведена на эталонной конфигурации и
  превращена в тест-кейс или точное описание условий.

  A_COMPLAINT_IS_A_CANDIDATE_FAILURE — жалоба есть кандидат на отказ;
  подтверждается воспроизведением (прямое следствие
  «LLM output ≠ verified copy» перенесённое на сигналы).

Невоспроизведённый сигнал: в очередь наблюдения, не в инъекцию.

====================================================================
5. КАНДИДАТ ОТ РИБОСОМЫ (правила R1–R3 guard-а)
====================================================================

- Работа только с копией; эталон заморожен (FROZEN ORIGINAL RULE).
- AI output = candidate, не integration (CANDIDATE STATUS RULE).
- Оформление: INJECTION_ID, дата, модель/версия, хеш входа, хеш выхода,
  ссылка на подтверждённый отказ из п. 4.

====================================================================
6. ОТБОР РЕДАКТОРОМ (четыре исхода)
====================================================================

| Исход | Действие |
|---|---|
| ACCEPT | кандидат идёт на proof test |
| MODIFY | редактор правит сам, затем proof test |
| REJECT | отказ с записью причины в журнал (отвергнутые инъекции — данные, не мусор) |
| RETURN | допзадание рибосоме: петля возвращается в п. 3 с уточнением |

RETURN — признак живого редактора: отбор не сводится к кнопке «да/нет».

====================================================================
7. PROOF TEST (до внедрения, всегда)
====================================================================

Минимум для software (по Software Continuity SOP):
clean build → полный прогон тестов → sample output совпадает
с заявленным/ожидаемым → плюс тест-кейс из п. 4 теперь зелёный.

REJUVENATION_WITHOUT_PROOF_TESTING_IS_DRIFT (формула guard-а 4.4).

====================================================================
8. ВНЕДРЕНИЕ И ЗАПИСЬ
====================================================================

- Команда на установку исходит ТОЛЬКО от редактора, после proof test.
  Самоустановка рибосомы запрещена (SELECTION BEFORE SCALE RULE):
  рибосома без подписи редактора — не клетка, а опухоль.
- Custody-запись: INJECTION_ID, исход (accept/modify/reject/return),
  кто утвердил, дата, хеши, результат proof test.

10. ГРАНИЦЫ
====================================================================

  не отменяет managed sunset (технология может уйти достойно).

  (PATTERN_VS_OBJECT DECLARATION, guard R6).
